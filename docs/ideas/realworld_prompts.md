# Real framework prompts: contact through a shared place (EXPLORATORY)

Generated by `experiments/realworld_prompts_report.py`; do not edit by hand. Status: EXPLORATORY, not pre-registered, run on 2026-11-07 after the confirmatory set was frozen. No result here is part of C1-C5.

Question. Our harness runs show that one sentence allowing agents to message each other through the shared store moves blocked agents from almost never writing to others to almost always doing so, and that a house rule limiting agents to their own artifacts stops them from using other jobs' work. How often do the default prompts of widely used open-source agent frameworks contain such wording, does the SwarmCheck linter (`src/swarm/swarmcheck/lint.py`) find it, and do the real sentences open the gate in our harness?

## What was collected

51 prompt texts from 28 projects (27 GitHub repositories): default system prompts, prompt templates, tool descriptions and official example prompts that configure an agent to work with other agents or with shared memory or a shared workspace. Frame: the multi-agent and memory parts of frameworks that we knew to be widely used (stars on 2026-11-07 in `results/realworld_prompts/sources.csv`), plus official examples where the framework itself ships no default (LangGraph tutorials, Google ADK samples, OpenAI Swarm, A2A samples, the Anthropic cookbook). One project contributes one to four prompts. This is a purposive sample, not a random one: prevalence below is over these prompts and projects. Microsoft Agent Framework reuses the Magentic-One orchestrator prompts (the task-ledger prompt verbatim, the others lightly edited) and is counted under Magentic-One; AG2 keeps AutoGen's speaker-selection wording.

Every file was fetched from raw.githubusercontent.com at a pinned commit by `experiments/realworld_prompts_fetch.py` (Python sources parsed with `ast`, nothing executed). The texts are in `data/raw/framework_prompts/` (gitignored, regenerable); the table of repo, path, commit, date and link is `results/realworld_prompts/sources.csv`.

## Labels

Each prompt was read and labelled by hand before the linter was run on it (labels committed in 78c2c1b, linter results after). The annotator knew the linter's rules, so the labels are blind to its output, not to its design.

- contact_shared: the prompt grants or describes passing information to, or receiving it from, other agents by writing to or reading from a shared persistent place (memory, state, files, a board or task list, documents), as opposed to a direct message, handoff, delegation call or group-chat transcript.
- boundary_rule: a sentence that limits what the agent may read, use or change of data that others created (our house rule is one).
- shared_storage: the prompt mentions a store, memory or file space that the agent can write and that other agents, runs or users also read or write.
- borderline: cases where the decision was close (listed in the CSV note).

## Linter against the labels

| rule | label it should find | TP | FP | FN | TN | precision | recall |
|---|---|---|---|---|---|---|---|
| HIGH permission_to_coordinate | contact_shared | 0 | 0 | 11 | 40 | n/a | 0/11 = 0.00 [0.00, 0.26] |
| HIGH, borderline prompts dropped | contact_shared | 0 | 0 | 9 | 39 | n/a | 0/9 = 0.00 [0.00, 0.30] |
| MED missing_boundary_rule | shared storage, no boundary | 2 | 0 | 12 | 37 | 2/2 = 1.00 [0.34, 1.00] | 2/14 = 0.14 [0.04, 0.40] |
| MED, borderline prompts dropped | shared storage, no boundary | 2 | 0 | 9 | 37 | 2/2 = 1.00 [0.34, 1.00] | 2/11 = 0.18 [0.05, 0.48] |

The linter raised HIGH on none of the 51 prompts, so its precision for HIGH is undefined and its recall is the row above. Its patterns were written for the harness wording ("notes ... in the store", "other jobs read", "/shared", "artifact store"). Real prompts name the shared place differently: memory, state keys, a shared task list, documents, outlines, file paths, "shared knowledge from previous agents". MED missing_boundary_rule fired on `crewai__memory_tools`, `swarms__multi_agent_collab`; INFO benign_team_wording on `autogen__society_of_mind`, `openai_agents__handoff_prefix`, `swarms__multi_agent_collab`. Fitting new patterns to these 51 prompts and scoring them on the same prompts would overstate recall; a fix needs a held-out set.

## Harness test of the real sentences

Run in progress or not run yet: `experiments/realworld_prompts_harness.py` (arms plain, coordinate_ok and the twelve `REAL_CUES` arms, house rule on, 100 episodes per arm, 20 turns, adaption/deepseek-v4-flash, concurrency 16, own cache and ledger with a $15 cap). It resumes from its cache; rebuild this file when it has finished. No harness numbers are reported before then.

## Caveats

- One annotator; the contact_shared line between a shared place and a message channel is a judgement call (borderline cases flagged and dropped in a second row of the linter table).
- Prompts are what frameworks ship, not what deployments use: developers add their own instructions, and tools (not only prompt text) decide whether a shared store exists.
- The harness test moves a sentence out of its context into a data-cluster job. Names in it (state keys, subagents, Engineer, add_task_note) do not exist there. One model, one harness, one seed set, 100 episodes per arm; exploratory.
- No attack or misuse details are reported; excerpts are short quotes of public open-source prompts.

## Reproduce

```bash
uv run python -I experiments/realworld_prompts_fetch.py      # fetch at pinned commits
uv run python -I experiments/realworld_prompts_lint.py       # linter vs labels
caffeinate -i uv run python experiments/realworld_prompts_harness.py  # harness arms
uv run python -I experiments/realworld_prompts_report.py     # this file
```
